How to Run Your Tests Against Chrome

Intro​

Selenium drives each browser through a browser driver: a small program, made by the browser vendor, that receives the WebDriver commands and runs them in the browser. Chrome's driver is ChromeDriver, Firefox's is GeckoDriver, and so on.

For years, running tests on Chrome meant downloading the right ChromeDriver for our Chrome version, and telling Selenium where it was (in the PATH, or with a system property). Each Chrome update could break the tests until we downloaded a new driver.

A Solution​

Let Selenium Manager do it. It comes with Selenium (since 4.6), and runs when we start a browser without a driver:

  • It finds the Chrome installed on the machine and downloads the ChromeDriver that matches its version.
  • When Chrome is not installed (or we ask for a version that is not there), it downloads Chrome for Testing, an unbranded Chrome made for automation, and its ChromeDriver.
  • It keeps the downloads in a cache (~/.cache/selenium), so it downloads them only once.

The same goes for Firefox (GeckoDriver and Firefox) and Edge (msedgedriver). So, for now, a test only needs to ask for Chrome. No driver downloads, no paths.

What about Playwright?​

Playwright has a similar approach, but for the browsers. It doesn't use the browsers installed on the machine: npx playwright install downloads the browsers of each Playwright version, and Playwright drives them directly (no driver in between). These browsers are not the ones our users have:

  • chromium is a Chromium-based, unbranded build (Chrome for Testing in recent versions), not Google Chrome.
  • firefox and webkit are custom builds of Firefox and WebKit, patched by the Playwright team to support automation. The WebKit build is not Safari.

To test on the branded Google Chrome or Microsoft Edge installed on the machine, Playwright has the channel option (e.g., channel: 'chrome').

Expected Behavior​

With Selenium:

  • Selenium Manager finds Chrome and ChromeDriver (and downloads what is missing)
  • ChromeDriver starts
  • Chrome opens
  • The test loads the page, checks the title, and prints the versions of Chrome and ChromeDriver
  • Chrome closes
  • ChromeDriver stops

With Playwright, two tests:

  • The first one starts the Chromium build of Playwright, the second one the installed Google Chrome
  • Each test loads the page, checks the title, and prints the browser version
  • The browser closes

Summary​

Selenium Manager removes the setup that made browser drivers a pain: no downloads, no paths, no broken tests after a browser update. If you need to manage the drivers yourself (e.g., a machine without internet access), you can still put the driver in the PATH or pass its path to the driver service, and Selenium Manager steps aside. See the Selenium Manager documentation for its options.

Happy Testing!
