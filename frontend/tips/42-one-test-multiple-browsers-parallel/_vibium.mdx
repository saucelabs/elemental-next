## Code Walkthrough

### Connecting to Sauce Labs

Vibium speaks WebDriver BiDi, and Sauce Labs gives each session a BiDi WebSocket when we ask for one. So the helper in
`sauce.js` talks to Sauce Labs with plain WebDriver requests (`fetch`), and the test connects Vibium to the session.

- Lines 1 to 3 set the Sauce Labs URL (US West data center) and build the `Authorization` header from the
  `SAUCE_USERNAME` and `SAUCE_ACCESS_KEY` environment variables.
- Lines 5 to 12 send a WebDriver request to Sauce Labs and return its value.
- Lines 16 to 29 start a session on the latest version of the browser on Windows 11. `webSocketUrl: true` asks for the
  BiDi WebSocket, and `sauce:options` gives the job a name. It returns the session id and the WebSocket URL.
- Lines 32 to 38 mark the job as passed or failed on Sauce Labs (`sauce:job-result`), and end the session.

### The Test

Lines 1 to 3 pull in the `assert` module, Vibium's `browser`, and the helper. Line 5 lists the browsers: Chrome,
Firefox and Edge.

Lines 7 to 20 run the test on one browser: they start a session on Sauce Labs, connect Vibium to it, visit the page and
check its title. The `finally` block always closes the connection, and marks the job as passed or failed.

The `before` hook (lines 23 to 28) skips the test when the Sauce Labs credentials are not set.

The test (lines 30 to 32) calls `runOn` for every browser at the same time, and `Promise.all` waits for all of them.
If one of them fails, the test fails.
