## Code Walkthrough

### Configuring Sauce Labs

[Mobilewright](https://github.com/mobile-next/mobilewright) is a mobile test framework with the API of Playwright.
Where the tests run is part of the configuration: the [Sauce Labs driver](https://github.com/saucelabs/mobilewright-saucelabs)
(`@saucelabs/mobilewright-driver`) runs them on Sauce Labs real devices.

<TipCode codePath={"30-mobile/code/mobilewright/mobilewright.config.ts"} language={"ts"}/>

- Lines 5 to 8 skip the run when the Sauce Labs credentials are not set. Otherwise, the driver reads them from the
  `SAUCE_USERNAME` and `SAUCE_ACCESS_KEY` environment variables.
- Lines 13 to 18 set the timeouts. Finding a free device and installing the app can take a few minutes, and the 5
  second defaults of Mobilewright are meant for local devices. Line 15 runs one device at a time.
- Line 19 sets the Sauce Labs driver, the data center (`us-west-1`), and the name of the build on Sauce Labs.
- Lines 20 to 43 are one project for each platform. Each one asks for a device by a regular expression of its name
  (`deviceName`) and its OS version (`osVersion`), and installs the demo app from its GitHub release (`installApps`):
  Sauce Labs downloads it and installs it on the device. `bundleId` is the app that the tests open.

### The Test

The test (lines 3 to 5) checks that the catalog shows the backpack. `getByText` with a regular expression finds the
product on both platforms: its name is "Sauce Labs Backpack" on Android and "Sauce Labs Backpack - Black" on iOS.
`toBeVisible` waits for it, since the app shows a splash screen first.

Install the dependencies with `npm install`, then run the test by executing `npm test` from the command-line. It runs
the Android project first and then the iOS one (`mobilewright test --project android`, then `--project ios`), as the
Sauce Labs driver recommends running each platform in its own process. The tests show up on the Sauce Labs test results
page, with the video of each session.
