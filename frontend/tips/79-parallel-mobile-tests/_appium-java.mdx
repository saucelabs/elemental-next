## Code Walkthrough

### Running in Parallel

JUnit runs tests one at a time by default. The `junit-platform.properties` file in `src/test/resources` turns on its
parallel execution:

<TipCode codePath={"79-parallel-mobile-tests/code/appium-java/src/test/resources/junit-platform.properties"} language={"properties"}/>

- Line 1 turns on parallel execution, and line 2 runs every test (and every run of a parameterized test) at the same
  time.
- JUnit creates a new instance of the test class for each run, so each one has its own `driver` (line 30).

### The Test

- Lines 45 to 47 are one test with two runs, one for each platform (`@ParameterizedTest` with `@ValueSource`).
  With parallel execution on, both runs start at the same time.
- Line 48 starts the session for the platform, with `startDriver` (lines 57 to 74). It is the same as tip 30: the
  options of the platform, the app, and the Sauce Labs options, with the platform in the name of the test.
- Lines 50 to 52 pick the locator of the platform. The test is the same on both: only the way to find the backpack
  changes.
- Lines 53 and 54 wait up to 30 seconds for the backpack and check that it is displayed.
- Lines 32 to 43 skip the test when the Sauce Labs credentials are not set, and end the session after each run.
