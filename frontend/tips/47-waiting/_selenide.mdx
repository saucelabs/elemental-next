### How Selenide Waits

Selenide doesn't use implicit waits or `WebDriverWait`. Every check (`shouldBe`, `shouldHave`, ...) and every action
(`click`, `setValue`, ...) waits for the element on its own, up to a timeout of 4 seconds by default. The loading bar
of the page takes about 5 seconds, so the default timeout is too short here.

### The Default Timeout Gives Up Before the Element Is Rendered

In lines 21 to 25, the element is added to the page after the loading bar. The check gives up after 4 seconds and
throws `ElementNotFound`.

### The Default Timeout Gives Up While the Element Is Hidden

In lines 28 to 32, the element is on the page but hidden. Selenide finds it, but it is not visible yet after 4
seconds, so the check throws `ElementShould`.

### A Longer Timeout

Lines 35 to 40 run once for each example. `shouldBe(visible, Duration.ofSeconds(10))` gives this check a longer
timeout, so it waits until the element is visible, whether it was hidden or missing. Then we check its text.

To change the timeout of every check, set `Configuration.timeout` (in milliseconds), or the `selenide.timeout`
system property.
