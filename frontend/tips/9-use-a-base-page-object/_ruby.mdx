## Code Walkthrough

### The Base Page Object

`BasePage` is a simple Ruby class. We use `attr_reader` to store the Selenium WebDriver instance that gets passed
to it through the `initialize` method, and the rest of the class is filled with common Selenium actions:
`visit`, `find`, `click_on`, `type`, `displayed?`, `text_of`, `title`, and `wait_for`.

Note that `displayed?` returns `false` when the element is not on the page (by rescuing
`Selenium::WebDriver::Error::NoSuchElementError`). That lets `wait_for` use it until the element is displayed.

### The Page Objects

`DynamicLoadingPage` and `LoginPage` inherit from it (with `< BasePage` after the class name). Since we have some
actions we want to execute when we create them, we keep them in the `initialize` method. But since we are
inheriting from `BasePage`, we need to call `super` before them. This is responsible for passing the driver object
into the Base Page Object and making all of its methods run smoothly.

Each method now reads like a description of the page behavior (e.g., `click_on START_BUTTON`), with no Selenium
code in it.

### The Test

The `setup`, `teardown`, and `run` methods launch Firefox before each test and quit it afterward. The tests
create the Page Objects and use their methods, just like in the previous tip.
