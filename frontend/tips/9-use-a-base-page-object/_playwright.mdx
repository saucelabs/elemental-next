## Code Walkthrough

### The Base Page

<TipCode codePath={"9-use-a-base-page-object/code/playwright/pages/basePage.ts"} language={"ts"}/>

The base page holds what every page object needs. It keeps the Playwright `page` (lines 8 to 10) and has a `visit`
method (lines 12 to 15) that goes to a path of the site and checks the title.

Playwright already has short methods to click, fill and wait (e.g., `locator.click()`, `locator.fill()`), so the
base page doesn't need to wrap them. In Selenium, the base page usually wraps those actions to add waits.

### The Page Objects

<TipCode codePath={"9-use-a-base-page-object/code/playwright/pages/dynamicLoadingPage.ts"} language={"ts"}/>

<TipCode codePath={"9-use-a-base-page-object/code/playwright/pages/loginPage.ts"} language={"ts"}/>

Both page objects extend `BasePage`. They declare their locators as fields, using the `page` of the base page, and
use `visit` to load their page. The login page also has a `loginAs` method that fills the form and submits it.

### The Tests

The first test (lines 5 to 10) loads the dynamic loading page, clicks start and checks the text. The second test
(lines 12 to 17) logs in and checks that the success message is visible. `toHaveText` and `toBeVisible` wait for the
elements, so the page objects don't need wait methods.
