## Code Walkthrough

### Importing Libraries

Lines 1 to 9 pull in `assert`, Selenium, and the classes of Selenium's BiDi `network` module that build the intercept
and the mocked response.

### Setup and Teardown

The `beforeEach` method (lines 14 to 18) turns on WebDriver BiDi with `enableBidi()` and starts Chrome. The
`afterEach` method (lines 20 to 24) quits the browser.

### The Test

Lines 26 to 46 are the test itself.

Line 29 builds the URL pattern of the requests to mock. It has only the host name and the path (`/slow_api/data`), so
it matches the API calls with any query string. Line 30 adds an intercept for it, in the `BEFORE_REQUEST_SENT` phase:
the browser pauses the matching requests before it sends them. The other requests load as usual.

`beforeRequestSent` (lines 31 to 38) is called for each request. For the API calls, `provideResponse` answers them: a
`200`, a JSON content type, and a JSON body with the message. The request never reaches the server.

Then the test loads the page and clicks the button. The page calls the API, gets the mocked response, and shows its
message. The test waits for the message in the status line, and checks the attempt in the list (`200: Hello from the
mock`).
