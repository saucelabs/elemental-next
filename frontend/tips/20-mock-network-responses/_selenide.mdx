## Code Walkthrough

### Importing Libraries

Lines 3 to 14 pull in Selenide (`$`, `open`, the `exactText` condition, and its proxy) and JUnit.

### Setup and Teardown

The `setUp` method (lines 17 to 22) sets `Configuration.proxyEnabled`, so Selenide starts the browser behind its own
proxy, and opens the page. Every request of the browser goes through the proxy, and the proxy can answer them itself.
The `tearDown` method (lines 24 to 27) closes the browser.

### The Test

Lines 29 to 38 are the test itself.

`responseMocker().mockText` (lines 31 to 33) tells the proxy to answer the `GET` requests whose URL starts with
`/slow_api/data` with the given text (a JSON body with the message, and a `200`). The request never reaches the
server. The other requests load as usual.

Then the test clicks the button. The page calls the API, gets the mocked response, and shows its message.
`shouldHave` waits for the message in the status line, and for the attempt in the list (`200: Hello from the mock`).

### Executing the Test

Before executing the test, we need to make sure the required libraries are declared on the `pom.xml` file. The proxy
comes in the `selenide-proxy` library.
