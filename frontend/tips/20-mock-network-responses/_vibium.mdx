## Code Walkthrough

### Importing Libraries

Lines 1 and 2 pull in the `assert` module for the assertions and Vibium's `browser` to drive the browser.

### Setup and Teardown

After creating a `describe` to group our tests, lines 8 to 15 start and stop the browser.

The `beforeEach` method runs before each test. It starts the browser with `browser.start()` and gets its first page
(tab) with `bro.page()`. The `afterEach` method runs after each test and closes the browser with `bro.stop()`.

### The Test

Lines 17 to 32 are the test itself.

`page.route` (lines 18 to 23) intercepts the requests whose URL matches `**/slow_api/data?*`, and `route.fulfill`
answers them with a JSON content type and a JSON body with the message (the status is `200`). The request never
reaches the server. The pattern is a glob: `**` matches the start of the URL, and `?*` matches the query string, which changes with the
options of the form. The other requests load as usual.

Then the test loads the page and clicks the button. The page calls the API, gets the mocked response, and shows its
message. `find` waits for the element to exist, so it waits for the answer in the list. The test checks the attempt
(`200: Hello from the mock`) and the message in the status line.
