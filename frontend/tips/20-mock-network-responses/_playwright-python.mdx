## Code Walkthrough

### Importing Libraries

Line 1 pulls in Playwright's `Page`, `Route` and `expect`.

### Setup and Teardown

The `pytest-playwright` plugin handles the browser for us. Each test that takes a `page` argument receives a fresh
browser tab, and the plugin closes it when the test ends. There is no setup or teardown code to write.

### The Test

Lines 4 to 14 are the test itself.

The `mock` function (lines 5 and 6) answers a request with `route.fulfill`: a JSON body with the message (the `json`
option sets the content type, and the status is `200`). Line 8 registers it with `page.route` for the requests whose
URL matches `**/slow_api/data?*`. The request never reaches the server. The pattern is a glob: `**` matches the start of the URL, and `?*` matches the query string, which changes with the
options of the form. The other requests load as usual.

Then the test loads the page and clicks the button. The page calls the API, gets the mocked response, and shows its
message. `to_have_text` waits for the message in the status line, and for the attempt in the list (`200: Hello from
the mock`).
