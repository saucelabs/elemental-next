## Code Walkthrough

### Importing Libraries

Lines 1 to 4 pull in the libraries we need: Playwright, its MSTest integration, and MSTest itself.

### Setup and Teardown

Lines 8 and 9 declare the test class. It extends `PageTest`, from the `Microsoft.Playwright.MSTest.v4` package.
`PageTest` handles the browser for us: each test gets a fresh browser tab in the `Page` property, and it is closed
when the test ends. There is no setup or teardown code to write.

### The Test

Lines 11 to 27 are the test itself.

`RouteAsync` (lines 14 to 20) intercepts the requests whose URL matches `**/slow_api/data?*`, and `FulfillAsync`
answers them with a JSON body with the message (the `Json` option sets the content type, and the status is `200`).
The request never reaches the server. The pattern is a glob: `**` matches the start of the URL, and `?*` matches the query string, which changes with the
options of the form. The other requests load as usual.

Then the test loads the page and clicks the button. The page calls the API, gets the mocked response, and shows its
message. `ToHaveTextAsync` waits for the message in the status line, and for the attempt in the list (`200: Hello
from the mock`).
