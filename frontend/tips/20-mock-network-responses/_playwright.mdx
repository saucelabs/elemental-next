## Code Walkthrough

### Importing Libraries

Line 1 pulls in the Playwright test runner (`test` and `expect` from `@playwright/test`).

### Setup and Teardown

Playwright Test handles the browser for us. Each test receives a `page` (a fresh browser tab) as a fixture, and
Playwright closes it when the test ends. There is no setup or teardown code to write.

### The Test

Lines 3 to 13 are the test itself.

`page.route` (lines 4 to 6) intercepts the requests whose URL matches `**/slow_api/data?*`, and `route.fulfill`
answers them with a JSON body with the message (the `json` option sets the content type, and the status is `200`).
The request never reaches the server. The pattern is a glob: `**` matches the start of the URL, and `?*` matches the query string, which changes with the
options of the form. The other requests load as usual.

Then the test loads the page and clicks the button. The page calls the API, gets the mocked response, and shows its
message. `toHaveText` waits for the message in the status line, and for the attempt in the list (`200: Hello from
the mock`).
