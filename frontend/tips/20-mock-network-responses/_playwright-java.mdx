## Code Walkthrough

### Importing Libraries

Lines 3 to 8 pull in Playwright's assertions, `Page`, `Route` and JUnit extension, and JUnit's `@Test`.

### Setup and Teardown

Line 10 adds `@UsePlaywright` to the test class. It's Playwright's JUnit extension: it starts the browser and gives each
test that asks for a `Page` parameter a fresh browser tab, which it closes when the test ends. There is no setup or
teardown code to write.

### The Test

Lines 13 to 24 are the test itself.

`page.route` (lines 15 to 17) intercepts the requests whose URL matches `**/slow_api/data?*`, and `route.fulfill`
answers them with a JSON content type and a JSON body with the message (the status is `200`). The request never
reaches the server. The pattern is a glob: `**` matches the start of the URL, and `?*` matches the query string, which changes with the
options of the form. The other requests load as usual.

Then the test loads the page and clicks the button. The page calls the API, gets the mocked response, and shows its
message. `hasText` waits for the message in the status line, and for the attempt in the list (`200: Hello from the
mock`).
