## Code Walkthrough

### Setup and Teardown

The `setup` method (lines 6 to 11) turns on WebDriver BiDi with `web_socket_url`, and starts Chrome. The `teardown`
method (lines 13 to 15) quits the browser, and `run` (lines 17 to 22) calls them around the test.

### The Test

The test (lines 24 to 45) uses Selenium's BiDi `Network` module (line 25).

Line 27 is the URL pattern of the requests to mock. It has only the host name and the path (`/slow_api/data`), so it
matches the API calls with any query string. Line 28 sends the `network.addIntercept` command for it, in the
`beforeRequestSent` phase: the browser pauses the matching requests before it sends them. The other requests load as
usual.

The `before_request` handler (lines 29 to 38) is called for each request. When the request is paused by the
intercept (`isBlocked`), `provide_response` answers it: a `200`, a JSON content type, and a JSON body with the
message. The request never reaches the server.

Then the test loads the page and clicks the button. The page calls the API, gets the mocked response, and shows its
message. The test waits for the message in the status line, and checks the attempt in the list (`200: Hello from the
mock`).
