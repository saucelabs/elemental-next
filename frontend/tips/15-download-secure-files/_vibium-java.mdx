## Code Walkthrough

### Setup and Teardown

Line 20 creates Java's `HttpClient`, which we use to check the files. It doesn't follow redirects, which we need for
the second example.

The `beforeEach` method (lines 25 to 29) starts the browser and gets its first page (tab). The `afterEach` method
(lines 31 to 36) closes the browser.

### Example 1: Files Behind Basic Auth

Lines 38 to 52 are the first test.

We visit the page with the files with the user and password in the URL (`https://admin:admin@...`), and get the link
of the first file. (In the Java client, version 26.8.21, `setHeaders` is not enough for basic auth, so we don't use it
like the JavaScript and Python examples do.)

The `HttpClient` doesn't know about the browser, so we send the credentials in the `Authorization` header, as `Basic`
followed by `user:password` in Base64. We send a `HEAD` request for the file and check that it answers with status
`200`.

### Example 2: A Page Behind a Form Login

Lines 54 to 75 log in with the form and wait for the success message. The site keeps the session in a cookie called
`rack.session`.

We get the cookies of the page's context with `page.context().cookies()` and send that one in the `Cookie` header of a
request for `/secure`. With the cookie, it answers with `200`. Without it, it answers with `302` (a redirect to the
login page).
