# How to Simulate Slow Connections

## Intro

With Selenium, we have the luxury of cross browser testing. But what happens when we also need to test how our
application behaves on a _slow_ connection?

## A Solution

Chrome can limit its own network, like the network throttling of its DevTools. Selenium sets these limits with the
network conditions command of ChromeDriver (it works with Microsoft Edge too). We set three values:

- **Latency**: how long each request waits before it goes out, in milliseconds.
- **Download throughput**: the most the browser downloads per second, in bytes.
- **Upload throughput**: the most the browser uploads per second, in bytes.

Then the test runs as usual, and we see how the page behaves when it loads slowly. The command can also take the
browser offline.

Older versions of this tip used a proxy server (BrowserMob Proxy) to limit the bandwidth. The proxy is no longer
maintained, and Chrome does the same with no extra server. Firefox has no such command.

Let's continue with an example.

## Expected Behavior

- Chrome starts
- The test limits the network of Chrome
- The test loads the page, which loads slowly
- The test checks the heading of the page, and that the page took at least 3 seconds to load
- Chrome closes

## Summary

A slow network shows problems a fast one hides: timeouts that are too short, spinners that never go away, and buttons
we can click before the page is ready. Running a few tests with a slow network catches them before our users do.
