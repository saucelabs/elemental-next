## Code Walkthrough

The demo app locks its main screen to portrait in its manifest, so rotating the device doesn't change it. Espresso runs
inside the app, so it can ask the screen itself to rotate: the requested orientation of an activity overrides the
manifest.

### The Test

- Lines 25 to 28 open the demo app, as in [tip 30](/tips/30-mobile).
- Lines 29 and 30 wait for the catalog, since the app shows a splash screen first.
- Line 31 gets the activity on screen with `currentActivity` (lines 39 to 45). The app opens a splash screen first, and
  then the main screen, a different activity, so the test asks the activity monitor of AndroidX Test which one is
  resumed.
- Line 33 sets its requested orientation to landscape, on the main thread of the app.
- Line 34 waits for the catalog again: Android creates the screen again in the new orientation.
- Line 35 checks that the screen is in landscape.
- `waitUntilDisplayed` (lines 47 to 58) checks again every half second, for up to 30 seconds.

### Running on Sauce Labs

[saucectl](https://docs.saucelabs.com/dev/cli/saucectl/) uploads the app and the tests to Sauce Labs and runs them. It
reads its configuration from `.sauce/config.yml`:

```yaml
apiVersion: v1alpha
kind: espresso
sauce:
  region: us-west-1
  concurrency: 1
  metadata:
    build: Elemental Selenium - Tip 86 - Espresso
espresso:
  app: app/build/outputs/apk/app-under-test.apk
  testApp: app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
suites:
  - name: Rotate
    devices:
      - name: Google.*
        options:
          deviceType: PHONE
artifacts:
  download:
    when: always
    match:
      - junit.xml
    directory: ./artifacts/
```

- `espresso` sets the app and the test app to upload. `./gradlew appUnderTest` builds both: the demo app, signed with
  the same key as the tests, and the test app.
- `suites` asks for a device. The name is a regular expression (`Google.*` is any Google device), and `deviceType:
  PHONE` leaves out the tablets. The tests run on the first free device that matches.
- `artifacts` downloads the JUnit report of the run into `artifacts/`.

### Executing the Test

[Install saucectl](https://docs.saucelabs.com/dev/cli/saucectl/#installing-saucectl) and set the `ANDROID_HOME`
environment variable to your Android SDK. Then build the tests and the app under test with `./gradlew appUnderTest`, and
run them by executing `saucectl run` from the command-line. saucectl prints the result of the run and the link to it on
Sauce Labs, with the video and the device logs.
