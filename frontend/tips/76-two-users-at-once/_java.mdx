## Code Walkthrough

### Importing Libraries

Lines 3 to 17 pull in `UUID` (for the room name), JUnit, Selenium, its BiDi `Browser` and `BrowsingContext` modules,
and the explicit wait (`WebDriverWait` and `ExpectedConditions`).

### Starting the Browser

Lines 21 and 22 build the URL of the chat with a random room. The `beforeEach` method (lines 25 to 31) starts Firefox
with WebDriver BiDi turned on (`enableBiDi`), and the `afterEach` method (lines 33 to 38) quits it.

### A Window for Each User

`newUserWindow` (lines 40 to 45) creates a user context with `createUserContext()` of the BiDi `Browser` module: a
fresh browser profile, with its own cookies and storage. Then it opens a window in that user context (a
`BrowsingContext` with `CreateContextParameters`), and returns its handle. The first window of the browser stays open,
unused.

### The Steps of a User

- `waitForText` (lines 47 to 50) waits up to 10 seconds until the text of an element contains the given text.
- `join` (lines 52 to 57) opens the chat, waits until the page is connected, types the name, and clicks "Join".
- `sendMessage` (lines 59 to 62) types the message and clicks "Send".

They act on the current window, so the same steps work for Alice and for Bob.

### The Test

Line 66 creates a window for Alice and line 67 one for Bob. Before each step, the test switches to the window of the
user with `driver.switchTo().window()`. Alice and Bob join (lines 69 to 72). Messages are not saved, so Alice waits
until she sees "Bob joined" before she writes "Hi Bob" (lines 74 to 77). Then Bob waits until his page shows it and
answers "Hi Alice" (lines 79 to 81), and Alice waits for the answer (lines 83 and 84). When the text doesn't show up,
the wait fails the test.
