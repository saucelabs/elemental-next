## Code Walkthrough

### Importing Libraries

Lines 1 to 8 pull in `System` (for `Guid` and `TimeSpan`), MSTest, Selenium, its BiDi API, and its support library
(for `WebDriverWait`).

### Starting the Browser

Lines 16 and 17 build the URL of the chat with a random room. The `SetUp` method (lines 21 to 28) starts Firefox with
WebDriver BiDi turned on (`UseWebSocketUrl`), and connects to it with `AsBiDiAsync()`. The `TearDown` method (lines 30
to 38) closes the BiDi connection and quits the browser.

### A Window for Each User

`NewUserWindow` (lines 40 to 47) creates a user context with `Browser.CreateUserContextAsync()`: a fresh browser
profile, with its own cookies and storage. Then it opens a window in that user context with
`BrowsingContext.CreateAsync`, and returns its handle. The first window of the browser stays open, unused.

### The Steps of a User

- `WaitForText` (lines 49 to 53) waits up to 10 seconds until the text of an element contains the given text.
- `Join` (lines 55 to 61) opens the chat, waits until the page is connected, types the name, and clicks "Join".
- `SendMessage` (lines 63 to 67) types the message and clicks "Send".

They act on the current window, so the same steps work for Alice and for Bob.

### The Test

Line 72 creates a window for Alice and line 73 one for Bob. Before each step, the test switches to the window of the
user with `_driver.SwitchTo().Window()`. Alice and Bob join (lines 75 to 78). Messages are not saved, so Alice waits
until she sees "Bob joined" before she writes "Hi Bob" (lines 80 to 83). Then Bob waits until his page shows it and
answers "Hi Alice" (lines 85 to 87), and Alice waits for the answer (lines 89 and 90). When the text doesn't show up,
the wait fails the test.
