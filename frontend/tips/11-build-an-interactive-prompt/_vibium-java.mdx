## Code Walkthrough

### Installing the Prompt

The Vibium CLI is the same for every language. It comes with the `vibium` npm package and the `vibium` Python package:
`npm install -g vibium` (or `pip install vibium`) puts a `vibium` command on our path (`vibium --version` checks that
it's there). The first time, `vibium install` downloads Chrome for Testing.

### Using the Prompt

`vibium start` starts a browser. It stays open in the background, so each of the next commands connects to it, runs
one Vibium command, prints what it did, and returns:

```
$ vibium go https://the-internet.herokuapp.com
Navigated to https://the-internet.herokuapp.com
```

Elements are found with CSS selectors. `vibium find` also finds them by role, text, label, placeholder, and more, and
gives each one a short name (e.g., `@e1`) that the next commands can use:

```
$ vibium find role link --name "Form Authentication"
@e1 [a] "Form Authentication"
$ vibium click @e1
Clicked element: #content > ul > li:nth-of-type(22) > a
```

`vibium map` lists all the elements we can interact with on the page, with the same short names. It helps when we
don't know the page yet.

When a command fails, the prompt tells us why and the browser stays where it was, so we can try again:

```
$ vibium click "#does-not-exist" --timeout 2s
Error: failed to click: timeout after 2s: element not found
```

A click doesn't wait for the next page to load. So after submitting the form, `vibium wait text` waits for the
message before `vibium text` reads it:

```
$ vibium wait text "You logged into a secure area!"
Text "You logged into a secure area!" found on page
$ vibium text "#flash"
You logged into a secure area!
            ×
```

`vibium stop` closes the browser and ends the session.

### Turning the Session into a Test

The Vibium CLI doesn't write the code for us, but each command matches a call of the Java API. So we copy the commands
that worked into a test, and leave out the one that failed.

The `beforeEach` method (lines 16 to 20) starts the browser and gets its first page (tab), like `vibium start`. The
`afterEach` method (lines 22 to 27) closes the browser, like `vibium stop`.

Lines 29 to 38 are the commands of the session: `vibium go` is `page.go`, `vibium find role link --name ...` is
`page.find(new SelectorOptions().role("link").text(...))`, `vibium fill` is `fill`, and `vibium click` is `click`. In
the test, `page.find` waits for the element on the next page, so we don't need the extra wait. Finally, we check that
the message starts with the text we expect (it ends with a `×` close button).
