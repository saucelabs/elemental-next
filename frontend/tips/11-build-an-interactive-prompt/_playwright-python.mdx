## TL;DR - Show Me The Code

We don't need to build the prompt ourselves: the Playwright CLI is one. We type commands in the terminal and see
them run in a browser that stays open between commands.

```bash
npm install -g @playwright/cli@latest

playwright-cli open https://the-internet.herokuapp.com --headed
playwright-cli find "Form Authentication"
playwright-cli click e53
playwright-cli fill "#username" tomsmith
playwright-cli fill "#password" "SuperSecretPassword!"
playwright-cli click "#does-not-exist"
playwright-cli click "button[type=submit]"
playwright-cli eval "() => document.querySelector('#flash').innerText"
playwright-cli close
```

## Code Walkthrough

### Installing the Prompt

The Playwright CLI comes with the `@playwright/cli` npm package. `npm install -g @playwright/cli@latest` puts a
`playwright-cli` command on our path (`playwright-cli --version` checks that it's there). It uses the Chrome
installed on our machine. `--browser` picks another one (`firefox`, `webkit` or `msedge`).

### Using the Prompt

`playwright-cli open` starts a browser (`--headed` shows its window) and goes to the URL. The browser stays open in
the background, so each of the next commands connects to it, runs one action, and prints the Playwright code it ran:

```
$ playwright-cli open https://the-internet.herokuapp.com --headed
### Browser `default` opened with pid 1592.
### Ran Playwright code
await page.goto('https://the-internet.herokuapp.com');
### Page
- Page URL: https://the-internet.herokuapp.com/
- Page Title: The Internet
```

Each command also saves a snapshot of the page in `.playwright-cli/`, where every element has a short name (e.g.,
`e53`). `playwright-cli find` searches that snapshot, and the next commands can use the short name instead of a
selector. The CLI turns it into a locator:

```
$ playwright-cli find "Form Authentication"
          - link "Form Authentication" [ref=e53] [cursor=pointer]:
$ playwright-cli click e53
### Ran Playwright code
await page.getByRole('link', { name: 'Form Authentication' }).click();
```

When a command fails, the prompt tells us why and the browser stays where it was, so we can try again:

```
$ playwright-cli click "#does-not-exist"
### Error
Error: "#does-not-exist" does not match any elements.
```

`playwright-cli eval` runs JavaScript in the page and prints the result, which is how we read the message after
logging in:

```
$ playwright-cli eval "() => document.querySelector('#flash').innerText"
### Result
" You logged into a secure area!\n×"
```

`playwright-cli close` closes the browser and ends the session. `playwright-cli --help` lists all the commands
(tabs, cookies, network requests, screenshots, ...).

### Turning the Session into a Test

The Playwright CLI prints the code of each command in JavaScript. Playwright for Python has the same methods, with
names in snake case (`getByRole` is `get_by_role`) and keyword arguments for the options (`{ name: '...' }` is
`name='...'`). So we copy the code of the commands that worked into a test, and leave out the one that failed.

Lines 6 to 10 are that code. The `pytest-playwright` plugin gives the test a new page and closes the browser when it
ends, like `playwright-cli open` and `playwright-cli close`. Finally, line 11 checks the message with
`to_contain_text`, which waits until it shows up (it ends with a `×` close button).
