## Code Walkthrough

### The Data

`user_data.csv` has one row per test case: the type of account, the username, the password, and the message we
expect after logging in.

### Importing Libraries

Lines 3 to 8 pull in the JUnit annotations for parameterized tests and the Selenide methods we use (`open`, `$` and
the `text` condition).

### The Test

Lines 11 and 12 tell JUnit to run the test once for each row of `user_data.csv` (skipping the header), and to name
each run after the first column (e.g., `bad_password`).

Lines 13 to 19 log in with the username and password of the row, and check the message. `text` checks that the
element contains the given text, ignoring the case, so the close button (`×`) at the end of the message doesn't get
in the way. Like every Selenide check, `shouldHave` waits for the message to show up.
