## Code Walkthrough

### Setup and Teardown

`BaseTest` has the setup and teardown that all our test classes share: it launches Firefox and loads the page before
each test (`@BeforeEach`), and quits it afterward (`@AfterEach`). JUnit creates a new instance of the test class for
each test, so each test gets its own driver.

### The Tests

Each test class has the tests for one of the tables and extends `BaseTest`.

After the clicks, `waitForSort` waits until the header has the class `headerSortDown` (ascending) or
`headerSortUp` (descending). The page sorts the table after the click, so reading the cells right away
could get them in the old order.

### Running in Parallel

JUnit runs tests one at a time out of the box. The `junit-platform.properties` file in `src/test/resources` turns
on parallel execution, runs both the classes and their methods concurrently, and uses a fixed parallelism of 2
threads.
