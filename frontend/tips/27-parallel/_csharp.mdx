## Code Walkthrough

### Setup and Teardown

`BaseTest` has the setup and teardown that all our test classes share: it launches Firefox and loads the page before
each test (`[TestInitialize]`), and quits it afterward (`[TestCleanup]`). MSTest creates a new instance of the test
class for each test, so each test gets its own driver.

### The Tests

Each test class has the tests for one of the tables and inherits from `BaseTest`.

After the clicks, `WaitForSort` waits until the header has the class `headerSortDown` (ascending) or
`headerSortUp` (descending). The page sorts the table after the click, so reading the cells right away
could get them in the old order.

### Running in Parallel

MSTest runs tests one at a time out of the box. The `[assembly: Parallelize(...)]` attribute in `AssemblyInfo.cs`
turns on parallel execution for the whole project, with 2 workers and at the method level (each test method can run
at the same time as any other).

### Executing the Test

Before executing the test, we need to make sure the required dependencies are declared on the project file (e.g.,
`csharp.csproj` in this case).
