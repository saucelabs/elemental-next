## Code Walkthrough

### Running Tests in Parallel

JUnit runs tests in parallel when `junit-platform.properties` says so. Ours runs the test classes and their tests at
the same time (`concurrent`), with up to 2 at once (`fixed.parallelism = 2`).

### The Base Test

`BaseTest` holds what both test classes share:

- Lines 10 and 11 hold a comparator that sorts the dues by their amount (e.g., `$51.00` before `$100.00`).
- Lines 14 to 17 open the tables page before each test.

We don't create or close a browser. Selenide keeps one browser per thread, and JUnit runs the parallel tests in
different threads, so each test gets its own browser. Selenide closes them when the tests finish.

### The Tests

The two test classes sort the dues of a table, in ascending and in descending order. `SortWithoutAttributesTest` uses
the first table, with locators based on the position of the column (`td:nth-of-type(4)`). `SortWithAttributesTest`
uses the second table, with the classes on the cells (`.dues`).

Each test takes the texts of the cells, sorts them to know the order we expect, clicks the header (twice for
descending order), and checks the order with `shouldHave(exactTexts(...))`. That check waits until the table is
sorted.
