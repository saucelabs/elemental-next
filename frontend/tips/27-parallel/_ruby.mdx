## Code Walkthrough

### Setup and Teardown

In RSpec, test files are referred to as 'specs'. We move our setup and teardown into `spec/spec_helper.rb` (in RSpec
parlance) with `RSpec.configure`: before each test it launches Firefox and loads the page, and after each test it
quits it. Each spec requires it at the top (`require 'spec_helper'`).

### The Tests

Each spec file has the tests for one of the tables. Its tests are grouped with `describe` and `context` blocks, and
defined within `it` blocks.

After the clicks, `wait_for_sort` waits until the header has the class `headerSortDown` (ascending) or
`headerSortUp` (descending). The page sorts the table after the click, so reading the cells right away
could get them in the old order.

### Running in Parallel

RSpec runs specs one at a time out of the box. The [parallel_tests](https://github.com/grosser/parallel_tests) gem
(in the `Gemfile`) runs them in several processes with `bundle exec parallel_rspec spec`. It splits the work by file,
which is why we broke our tests up into two spec files. `run_in_parallel.rb` runs that same command, so you can
also run `ruby run_in_parallel.rb`.
