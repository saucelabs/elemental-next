## Code Walkthrough

### Setup and Teardown

- Line 24 is the Sauce Labs URL for the `us-west-1` data center, and line 25 is the site under test.
- Lines 30 to 34 skip the tests when the Sauce Labs credentials are not set. `Assumptions.assumeTrue` aborts the test,
  which reports it as skipped.
- Lines 36 to 41 end the session after each test, which frees the device.

### Opening the Browser

Lines 76 to 96 start a session on Sauce Labs with the browser of the device.

- Lines 77 to 81 are the Sauce Labs options (`sauce:options`): the credentials, the Appium version and the name of the
  test on Sauce Labs. The Appium version is a fixed one (`appium3-2026-11`): with `latest`, Safari doesn't always load
  the page the test opens.
- Lines 85 to 88 ask for any Google phone (`Google.*`) with the `UiAutomator2` Appium driver. On Sauce Labs, the device
  name is a regular expression, and the test gets the first free device that matches. Line 86 sets `browserName` to
  `Chrome`: instead of installing an app, Appium opens Chrome.
- Lines 90 to 93 do the same on an iPhone, with the `XCUITest` Appium driver and Safari.
- Line 95 creates a wait of up to 30 seconds.

From here on, the driver works like a Selenium `WebDriver` in a desktop browser.

### The Tests

Each test runs twice, once on Android and once on iOS: `@ParameterizedTest` with `@ValueSource` passes the platform.

- Lines 45 to 61 open the home page of the-internet, tap the "Form Authentication" link, wait for the login form, type
  the user name and the password, and tap the login button. Lines 59 and 60 wait for the message at the top of the
  page and check that it welcomes the user.
- Lines 65 to 74 open the checkboxes page, check that the first checkbox is not checked, tap it, and check that it is.

Two things are different from a desktop browser:

- Safari on a real device doesn't always wait for the page to load before `get` returns. Lines 49 and 69 wait for the
  first element the test needs, instead of looking for it right away.
- The device types with its on-screen keyboard, which takes the bottom half of the screen. On Android, it can cover the
  login button, and the tap lands on the keyboard. Lines 54 to 56 hide it first (`hideKeyboard`). On iOS, Safari
  scrolls the page above the keyboard.

### Executing the Test

Before executing the test, we need to make sure the required dependencies are declared on the `pom.xml` file. The
Appium Java client brings Selenium with it, `selenium-support` adds the waits, and `junit-jupiter` includes the
parameterized tests.
