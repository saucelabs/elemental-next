## Code Walkthrough

### Connecting to Sauce Labs

Vibium speaks WebDriver BiDi, and Sauce Labs gives each session a BiDi WebSocket when we ask for one. So the helper in
`sauce.py` talks to Sauce Labs with plain WebDriver requests (`urllib`), and the test connects Vibium to the session.

- Line 6 sets the Sauce Labs URL (US West data center).
- Lines 9 to 21 send a WebDriver request to Sauce Labs and return its value. The `Authorization` header comes from the
  `SAUCE_USERNAME` and `SAUCE_ACCESS_KEY` environment variables.
- Lines 26 to 38 start a session on the latest version of the browser on Windows 11. `webSocketUrl: True` asks for the
  BiDi WebSocket, and `sauce:options` gives the job a name. It returns the session id and the WebSocket URL.
- Lines 42 to 47 mark the job as passed or failed on Sauce Labs (`sauce:job-result`), and end the session.

### The Test

Lines 1 to 4 pull in the `os` module, `pytest`, Vibium's `browser`, and the helper.

The fixture (lines 7 to 16) skips the test when the Sauce Labs credentials are not set. Then it starts a Chrome
session on Sauce Labs, connects Vibium to it with `browser.start(session['web_socket_url'])`, and gives the test its
first page (tab). After the test, it closes the connection, and marks the job as passed or failed with the result of
the test.

To know the result, `conftest.py` has a hook that saves the report of the test (`report_call`), the same one as in
the screenshot tip.

Before executing the test, we need to make sure the required libraries are declared on the `requirements.txt` file.

command-line. The first time, Vibium downloads Chrome for Testing.
