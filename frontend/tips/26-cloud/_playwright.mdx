## Code Walkthrough

### Running on Sauce Labs

Sauce Labs can start a browser for Playwright and let our tests drive it over the Playwright protocol, as if it ran on
our machine. The tests run here, and the browser runs on Sauce Labs, which records a video and the logs of the job.

`sauceLabs.ts` replaces the `page` that Playwright Test gives each test with a page of a browser on Sauce Labs:

- Lines 3 to 8 hold the addresses of Sauce Labs, the credentials, and the version of Playwright. Sauce Labs needs the
  major and minor version (e.g., `1.61`), and it supports only some versions, so `package.json` pins one of them.
- Lines 13 to 15 create an HTTP client with the credentials.
- Lines 18 to 30 ask Sauce Labs for a Chrome on Linux, with the name of the test and of the build. Sauce Labs answers
  with redirects (`303`) while it starts the browser, so we follow them until we get its address (`wsEndpoint`).
- Lines 33 to 35 connect to the browser with `chromium.connect`, give a new page to the test (`use`), and close the
  browser when the test ends.
- Lines 38 to 42 tell Sauce Labs if the test passed, using its REST API, and print the link to the job.

### The Test

The test file imports `test` from `sauceLabs.ts` instead of from Playwright (line 2). Lines 4 and 5 skip the test when
the Sauce Labs credentials are not set.

The test (lines 7 to 10) visits the page and checks the title. It is the same test we would run on our machine.
