## Code Walkthrough

### Importing Libraries

Lines 1 to 4 pull in Deque's `axe-core-api` gem, Selenium and RSpec. Line 8 lists the axe rules that the page breaks
on purpose.

### Setup and Teardown

The `setup` method (lines 10 to 12) starts Firefox. The `teardown` method (lines 14 to 16) quits it, and `run` (lines
18 to 23) calls them around each test.

### Scanning the Page

`scan` (lines 25 to 29) `Axe::Core` adds the axe-core script to the page, and runs the `Axe::API::Run` we give it.
`within` limits the scan to the `#widgets` section, and the scan returns the results: the violations, the rules that
passed, and the ones to review. The helper keeps the rule id of each violation. The ids are symbols, so it turns them
into strings.

### The Tests

The first test loads the page with the issues and checks that the scan reports every known issue (`KNOWN_ISSUES -
scan` is empty: no known issue is missing). It doesn't check that the scan reports only them: a newer version of axe
can add rules, or report a rule as "incomplete" when it can't be sure (like the color contrast of text that another
element covers).

The second test loads the fixed page and checks that the scan reports no violations (`be_empty`). This is the check to
use for our own pages.
