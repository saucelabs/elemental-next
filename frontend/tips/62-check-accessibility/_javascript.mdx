## Code Walkthrough

### Importing Libraries

Lines 1 to 3 pull in `assert`, Selenium, and Deque's `AxeBuilder` (from `@axe-core/webdriverjs`). Line 6 lists the axe
rules that the page breaks on purpose.

### Setup and Teardown

The `beforeEach` method (lines 11 to 13) starts Firefox, and the `afterEach` method (lines 15 to 17) quits it.

### Scanning the Page

`scan` (lines 19 to 23) `AxeBuilder` adds the axe-core script to the page and runs it with `analyze`. `include` limits
the scan to the `#widgets` section, and the scan returns the results: the violations, the rules that passed, and the
ones to review. The helper keeps the rule id of each violation.

### The Tests

The first test loads the page with the issues and checks that the scan reports every known issue (a loop that checks
each one, and names the missing rule when it fails). It doesn't check that the scan reports only them: a newer version
of axe can add rules, or report a rule as "incomplete" when it can't be sure (like the color contrast of text that
another element covers).

The second test loads the fixed page and checks that the scan reports no violations (`[]`). This is the check to
use for our own pages.
