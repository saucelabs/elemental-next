### Scanning the Page

There is no axe package for this tool yet, so the lines of `scan` (7 to 12) do what the packages do:
`browser.execute(axe.source)` adds the axe-core script to the page, and the second `browser.execute` runs
`axe.run("#widgets")` in the page, which scans only the `#widgets` section. `axe.run` returns a promise, and the tool
waits for its results: the violations, the rules that passed, and the ones to review. The helper keeps the rule id of
each violation. Deque's `@axe-core/webdriverio` package does the same, but it doesn't support WebdriverIO 10 yet.

### The Tests

The first test loads the page with the issues and checks that the scan reports every known issue
(`expect.arrayContaining`). It doesn't check that the scan reports only them: a newer version of axe can add rules, or
report a rule as "incomplete" when it can't be sure (like the color contrast of text that another element covers).

The second test loads the fixed page and checks that the scan reports no violations (`[]`). This is the check to
use for our own pages.
