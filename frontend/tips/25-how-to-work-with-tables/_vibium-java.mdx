## Code Walkthrough

### Importing Libraries

Lines 3 to 13 pull in Vibium's classes to drive the browser, JUnit to run the tests, and `Comparator` and `List` to
sort the values.

### Setup and Teardown

The `beforeEach` method (lines 19 to 24) starts the browser, gets its first page (tab), and visits the page with the
tables. The `afterEach` method (lines 26 to 31) closes the browser.

### Helpers

Lines 33 to 39 have two helpers. `texts` finds all the cells that match a selector with `page.findAll` and returns
their text. `dues` turns the text of the "Due" cells (e.g., `$50.00`) into numbers, so we can sort them.

### The Tests

The page has two tables. The first one has no classes or ids on its cells, so we find them by position (e.g.,
`td:nth-of-type(4)` is the fourth column, "Due"). The second one has classes on its cells (e.g., `dues`), which
makes the selectors easier to read.

Each test clicks the header of a column once (ascending) or twice (descending). The page sorts the table a moment
after the click, and marks the header with the class `headerSortDown` (ascending) or `headerSortUp` (descending).
So before reading the values, we wait for the header with that class (`page.find` waits for it). Then we check that
the values are in the same order as a sorted copy of them.

- Lines 41 to 47 sort the "Due" column of the first table in ascending order.
- Lines 49 to 56 sort it in descending order.
- Lines 58 to 64 sort the "Email" column, which is text.
- Lines 66 to 72 sort the "Due" column of the second table, using its classes.
