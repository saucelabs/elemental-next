# Fast and Reliable Test Setup with REST APIs

## Intro

This tip started as a guest post from Robert Schultheis, a Test Engineer at Knewton.

A good test is:

- **Precise.** It tests one thing. A bug in an unrelated part of the application should not make it fail.
- **Independent.** Other tests don't change its outcome.
- **Fast.** The quicker a test suite runs, the more useful it is.

These are hard to get in a Selenium test suite. Before a test can check anything, it often has to sign up, log in,
navigate, or fill in forms. Each step takes time, and each step can break, even when the feature under test works.

## A Solution

Many applications have a REST API behind the website. The test can use it for the setup: create the data it needs
with a few HTTP calls, and use the browser only for what it checks. The tests get faster, more focused, and more
reliable. Every language has an HTTP client, so this works in any test suite.

Two common steps:

- **Create the test data**, e.g., a new user for each test. A fresh user gives a clean slate: no other test changed
  it. Give it a unique name, so tests that run at the same time (on a Grid or in parallel CI jobs) don't share it.
  Delete it when the test is done.
- **Log in without the form.** If the API gives a session, add its cookie to the browser and go straight to the page
  under test. Keep one test that logs in through the form, so the login page is still covered.

## Example

[The-internet](https://the-internet.herokuapp.com) has a small API for this:

- `POST /api/users` with `{"username": "...", "password": "..."}` creates a user (`201`). The login form accepts it,
  and the secure area shows its name in `#username`.
- `POST /api/sessions` with the same JSON returns the session cookie (`rack.session`) of a logged-in user.
- `DELETE /api/users/<username>` deletes the user (`204`).

Users expire after 1 hour. Each example has two tests:

1. Creates a user with the API, logs in through the form, and checks the user name in the secure area.
2. Creates a user, gets a session from the API, adds the cookie to the browser, and opens the secure area directly.

Both delete their user at the end.

## Expected Behavior

- The test creates a user with a unique name through the API
- Chrome starts
- The first test logs in through the form; the second one adds the session cookie and opens the secure area
- The secure area shows the name of the new user
- Chrome closes, and the test deletes the user through the API

## Summary

Use the API for the setup and the browser for what the test checks. Creating data with an API takes milliseconds,
while the same steps in the UI take seconds and can break for reasons unrelated to the test. With unique data and a
cleanup step, the tests stay independent, even when they run at the same time.

Happy Testing!
