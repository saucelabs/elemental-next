## Code Walkthrough

### Setup and Teardown

`post` (lines 11 to 14) sends the user name and the password as JSON to a path of the API, with `Net::HTTP`.

The `setup` method (lines 16 to 22) creates the user. The name has a random part (`SecureRandom`), so tests that run
at the same time don't share a user. It checks the `201`, and starts Chrome. The `teardown` method (lines 24 to 28)
quits the browser and deletes the user. `run` (lines 30 to 35) calls them around each test, so the user is deleted
even when the test fails.

### The Tests

`logged_in_user` (lines 37 to 41) waits until the secure area shows the user name, and returns it.

The first test (lines 43 to 50) opens the login page, types the user name and the password, submits the form, and checks the name in the
secure area.

The second test (lines 52 to 63) posts the same JSON to `/api/sessions`, and takes the value of the `rack.session`
cookie from the `Set-Cookie` header. The browser accepts cookies only for the site it shows, so the test opens the login page first, adds the cookie, and
then opens the secure area directly.
